Telegram-скринер перегріву і short watch на USDT-перпетуалах. Повний опис логіки, порогів і поточного стану: @PROJECT_CONTEXT.md. Прочитай його перед будь-якою роботою.

## Хто користувач
Користувач не програміст. Спілкуйся українською. Пояснюй простими словами, технічні кроки для нього подавай по одному. Для будь-якої дії, яку має виконати він сам (секрети, налаштування, запуск), давай точну покрокову інструкцію.

## Головні правила
1. **Алгоритми не змінювати без явної згоди користувача.** Пороги, фактори, дерево класифікації, формули RSI і оцінок змінюються лише за окремим завданням. Якщо завдання «чисте перенесення» (наприклад, зміна біржі), логіка аналізу має лишитись тією самою.
2. **Не пушити в `main` напряму.** Усі зміни: нова гілка, потім pull request. Користувач сам зливає PR.
3. **Малі кроки.** Змінюй код невеликими перевірюваними частинами. Після кожної частини напиши, що змінено і як це перевірити.
4. **Перед PR запускай `python main.py --self-test`.** Усі тести мають проходити. У PR напиши результат.
5. **Не чіпай секрети.** Токени й ключі (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `GITHUB_TOKEN`, секрети проксі) не вписуються в код, логи чи коміти. Вони лише в GitHub Secrets і секретах Cloudflare.
6. **Оновлюй `SCRIPT_VERSION`** у `main.py`, коли змінюється поведінка, і додавай нову версію в опис PR.
7. Якщо чогось не вистачає для завдання або воно суперечить цим правилам, зупинись і запитай користувача, а не вгадуй.

## Архітектура коротко
- Cloudflare Worker (`ladovka-screener-dispatcher`) за cron раз на годину і за командою `/run` запускає GitHub Actions workflow `screener.yml`. Далі виконується `python main.py`, звіт іде в Telegram.
- Код Worker (`worker.js`) живе в Cloudflare, у цьому репозиторії його немає. Зміни для Worker подавай користувачу готовим текстом і інструкцією, як вставити.
- GitHub Actions не може звертатися до Bybit API напряму (HTTP 403, геоблок). Тому запити до Bybit мають іти через проксі в Cloudflare Worker (див. `bybit-migration-task-free.md` у документах проєкту). Прямих запитів Python до `api.bybit.com` не додавати.

## Файли
- `main.py` — весь аналіз і відправка в Telegram.
- `.github/workflows/screener.yml` — основний workflow (запускається лише вручну або з Worker).
- `bitget_screener_test.py`, `main_multi_test.py`, `provider_test.py`, `bybit_test.py`, `main_backup_2026 06 08` та тестові workflow — допоміжні. Без прямого завдання їх не змінювати і не видаляти.
- `README.md` застарів (описує OKX). Оновлюється окремим завданням.
